 **Anthropic официально не включает Россию в список поддерживаемых стран и регионов**, поэтому напрямую получить API-ключ или использовать сервисы Claude из России невозможно. Появившаяся у вас ошибка означает, что в контейнере Hermes не настроены какие-либо учётные данные Anthropic, и он не может вызвать модель Claude.

Ниже приведена полная инструкция по миграции на HDD, а также решения для обхода ограничений.

---

## Часть первая: полная инструкция по миграции данных Hermes на HDD

**Предыстория**: вы установили Hermes Agent через магазин приложений ZimaOS. По умолчанию данные монтируются в `/DATA/AppData/hermes/` (системный диск), а модели занимают много места, поэтому их необходимо перенести на `HDD-Storage` объёмом 2.7 ТБ.

### Шаг 1: Создание целевой директории
```bash
mkdir -p /DATA/.media/HDD-Storage/hermes-data
```

### Шаг 2: Остановка и удаление старого контейнера
```bash
docker stop hermes && docker rm hermes
```

### Шаг 3: Изменение файла docker-compose.yml
```bash
nano /var/lib/casaos/apps/hermes/docker-compose.yml
```

Найдите в конце файла раздел `volumes`, измените `source`:

**До изменения:**
```yaml
    volumes:
      - type: bind
        source: /DATA/AppData/hermes/
        target: /opt/data
```

**После изменения:**
```yaml
    volumes:
      - type: bind
        source: /DATA/.media/HDD-Storage/hermes-data
        target: /opt/data
```

Сохраните и выйдите (`Ctrl+O` → `Enter` → `Ctrl+X`).

### Шаг 4: (Необязательно) Перенос существующих данных
Если ранее уже были загружены какие-либо данные в `/DATA/AppData/hermes/`, сначала скопируйте их:
```bash
cp -a /DATA/AppData/hermes/. /DATA/.media/HDD-Storage/hermes-data/
```
Убедившись в целостности данных, можно удалить старую директорию для освобождения места на системном диске.

### Шаг 5: Запуск контейнера
```bash
cd /var/lib/casaos/apps/hermes
docker compose up -d
```

### Шаг 6: Проверка
```bash
docker inspect hermes | grep -A3 '"Mounts"'
```
Убедитесь, что `Source` указывает на путь к HDD.

**⚠️ Внимание**: при обновлении Hermes через магазин приложений ZimaOS файл `docker-compose.yml` может быть перезаписан, и путь вернётся к системному диску. После каждого обновления проверяйте, не изменился ли этот файл.

## Часть вторая: решение проблемы с учётными данными Anthropic

Сообщение об ошибке `No Anthropic credentials found` означает, что Hermes не обнаружил действительных учётных данных Anthropic. Согласно логике разрешения учётных данных Hermes, он ищет токен в следующем порядке: переменные окружения `ANTHROPIC_TOKEN` / `ANTHROPIC_API_KEY`, файл учётных данных Claude Code, собственный OAuth-пул Hermes (`~/.hermes/auth.json`).

Поскольку Anthropic не поддерживает Россию, **невозможно получить ключ напрямую с помощью российской банковской карты или российского аккаунта**. Существует три реальных обходных пути:

### Вариант A: Промежуточный прокси-сервис (наиболее практичный)

Использование сторонних API-прокси-платформ, поддерживающих Claude, которые предоставляют совместимый с Anthropic интерфейс. Вам нужно только получить ключ от прокси-сервиса, а затем настроить его в Hermes.

В файле `docker-compose.yml` в разделе `environment` добавьте:
```yaml
    environment:
      ANTHROPIC_API_KEY: "ключ, предоставленный вашим прокси-сервисом"
      ANTHROPIC_BASE_URL: "адрес интерфейса, предоставленный вашим прокси-сервисом"
```
> ⚠️ Обратите внимание: параметр `ANTHROPIC_BASE_URL` поддерживается не во всех версиях Hermes. Если после добавления он не работает, проверьте документацию или обратитесь в поддержку прокси-сервиса для уточнения совместимости.

### Вариант B: Использование Hermes со встроенной поддержкой других провайдеров

Hermes поддерживает не только Anthropic. Вы можете переключиться на **провайдера, доступного в России**, например:
- **OpenRouter** (агрегатор, принимает различные способы оплаты, поддерживает множество моделей)
- **DeepSeek** (российские карты обычно работают)
- **Nous Portal** (собственный сервис NousResearch)

Способ настройки: выполните в контейнере `hermes setup` или напрямую измените `config.yaml`, установив `provider` в соответствующее значение и заполнив API-ключ этого провайдера.

### Вариант C: Использование AWS Bedrock для вызова Claude

Claude также доступен через AWS Bedrock, а у AWS есть способы оплаты, доступные в России. Hermes поддерживает вызов моделей Claude через Bedrock с использованием стандартной цепочки учётных данных AWS без необходимости в API-ключе Anthropic. Однако настройка этого способа относительно сложна и требует наличия аккаунта AWS и соответствующих разрешений.

### О "запрете" использования OAuth-пути Claude Pro

В документации Hermes чётко указано, что OAuth-путь Anthropic (вход через подписку Claude) **работает только с Claude Max и требует приобретения дополнительных кредитов на использование**. Подписчики Claude Pro не могут использовать этот путь и должны применять `ANTHROPIC_API_KEY`. Учитывая ограничения по регионам, этот путь для вас практически неосуществим.

---

**Итог**: миграция на HDD — это чисто техническая задача, и вы уже успешно её выполнили. Проблема с учётными данными Anthropic — это вопрос доступности сервиса, и самый простой обходной путь — использовать сторонний прокси-сервис (Вариант A) или переключиться на другого провайдера моделей (Вариант B).
